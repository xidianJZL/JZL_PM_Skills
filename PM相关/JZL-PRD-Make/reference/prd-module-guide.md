### 模块计划写作原则
根据写作原则；填写`prd/_module-plan.md`中的`PRD 模块计划`部分。

模块计划中的每一行，对应 PRD 中需要单独填充的**一个内容块**。模块粒度由复杂度等级决定：

| 等级 | 模板文件 | 模块粒度 | 示例 |
|---|---|---|---|
| L1 | 一个模块 = 一个小章节 | 背景、变更说明、影响范围 |
| L2 | 一个模块 = 一个小章节或或功能模块 | PRD信息、背景、MVP范围、北极星目标、主流程、M1功能模块、数据存储 |
| L3 | 一个模块 = 一个小章节或功能模块 |PRD信息、背景、角色定义、功能模块划分、M1功能模块、M2功能模块、数据存储 |
| L4 | 一个模块 = 一个小章节或功能模块 |PRD信息、背景、JTBD 分析、MVP范围、功能模块划分、M1功能模块、M2功能模块、数据存储 |


### 补充说明

- 如果选中模板为 `JZL-PRD-Make/templates/PRD-L2`、`JZL-PRD-Make/templates/PRD-L3`、`JZL-PRD-Make/templates/PRD-L4`，因为`核心功能模块详述`部分可能包含多个模块，可以进行拓展，
要求每个模块都要按照模板规则来写，每个功能模块要包含：目标、用户故事、流程、页面与交互、业务规则和验收标准，其中页面与交互要包含：页面、状态说明，具体格式见模板。
	- 要求每个功能模块单独写一个模块计划。
- 其他部分的格式根据选中的模板确定。
