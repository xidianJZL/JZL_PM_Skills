# JZL-vibeCoding-function-prompt

根据用户的功能描述，按6大模块生成高质量vibecoding prompt文件。

## 硬约束

- **先预览再写入**：每个模块必须先在聊天里预览，用户确认后才写入文件，绝不能跳过预览步骤
- **确认即写入**：用户确认后必须立即将该模块写入文件，不能等所有模块预览完再批量写入
- **HITL反问上限**：最多问3个澄清问题
- **模块确认来回上限**：每个模块最多来回2轮，仍不确认则写"⚠️待确认"继续
- **自检重试上限**：不合格模块最多重写2轮

## 输入

用户输入的功能描述（纯文字），可以是：
- 极简："做个评论管理后台"
- 中等："会员积分商城：用户完成任务得积分，换奖品，要Web端"
- 完整：200-500字的产品想法

### 占位符规则

当用户输入含"我没想清楚"、"待定"、"占位提问"等关键词时，在prompt对应位置使用占位符而非脑补：

```
--- [待定]需澄清以下问题才能补齐:
- 问题1
- 问题2
---
```

占位符最多出现5次。

## 工作流

### 步骤1：初始化工作空间
1. 解析功能名（从用户输入中提取或反问）
2. 使用`scripts/create-workspace.js`脚本创建工作目录（兼容Windows/macOS/Linux）：

```bash
node scripts/create-workspace.js <功能名称>
```

脚本会自动：
1. 清理功能名中的特殊字符
2. 生成时间戳格式`YYYYMMDD-HHmm`
3. 创建`vibecoding-prompt-<功能名>-<时间戳>/`目录
4. 在目录内创建`prompt.md`，写入标题和6个模块挂载点

脚本返回工作目录的绝对路径。

### 步骤2：理解用户需求

解析功能描述，提取：
- 功能名
- 目标用户
- 产品形态
- 技术线索

**输入过短时反问**（最多3个问题）：
- 功能名是什么？
- 目标用户是谁？
- 产品形态（Web/App/客户端）？

### 步骤3：逐模块预览确认循环

对6大模块逐个执行：

**3a. 生成模块内容**
按`references/vibecodingFunction.md`的架构填充当前模块，脑补字段打"⚠️假设"标注。

**3b. 聊天预览**
在聊天里展示当前模块的完整内容（Markdown代码块格式），同时附1-2个待确认问题。

**3c. 等待确认**
- 用户回复"可以"/"没问题"/"OK"/"基本可以"等正向词 → 通过
- 用户给出修正意见 → 更新内容后重新预览
- 来回超过2轮 → 写"⚠️待确认"标注后继续下一模块

**3d. 写入文件**
用户确认后，立即将该模块内容追加写入`<工作目录>/prompt.md`对应位置。

依次处理：模块1→模块2→模块3→模块4→模块5→模块6

### 步骤4：写入审查清单

读取`templates/审查清单自检模板.md`，将其内容追加写入`prompt.md`末尾。

### 步骤5：自检

按8条审查清单逐项打勾✅/❌/⚠️，更新`prompt.md`中的自检结论。

不合格模块最多重写2轮，仍不达标则在文件末尾附告警：

```
⚠️ 自检未通过：以下N条未达标（列出条目），建议人工补充
```

## 输出格式

### 文件结构

```
./vibecoding-prompt-<功能名>-<YYYYMMDD-HHmm>/
└── prompt.md
```

### prompt.md内容模板

读取`references/vibecodingFunction.md`作为内容模板基础，生成的prompt.md结构为：

```markdown
# Vibecoding Prompt: <功能名>

## 1. 产品概述
<按模板填充>

## 2. 页面与信息架构
<按模板填充>

## 3. 页面布局
<按模板填充>

## 4. 交互行为
<按模板填充>

## 5. 业务逻辑与数据逻辑
<按模板填充>

## 6. 技术与交付约束
<按模板填充>

## 审查清单自检
<使用templates/审查清单自检模板.md>
```

### 聊天回执

- 模块确认通过后输出一行："✅ 模块N/6已确认并写入"
- 全部完成后输出最终回执：文件路径 + "✅ 全部完成 / ⚠️ N个待确认"

## 资源文件

- `references/vibecodingFunction.md` - 6大模块架构源
- `templates/审查清单自检模板.md` - 8条打勾格式
- `scripts/create-workspace.js` - 创建工作目录脚本（Node.js，跨平台）

## 安全边界

- 不输出真正的代码（只输出prompt）
- 脑补字段必须标`⚠️假设`
- 只创建新目录/文件，从不修改项目已有内容
