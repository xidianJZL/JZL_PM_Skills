# JZL-skill-grill

> 本 skill 基于 `SKILL-grill.md` 制作，引导大模型与用户进行 6 轮焦点式对话，最终产出 `SKILL-draft.md`。

## 工具定位

`JZL-skill-grill` 是一个**多轮对话定型器**，不是直接产出 Skill 代码的工具：

- 用户有"我想做个 skill"这种模糊想法
- 大模型按本剧本引导，进行 **6 轮焦点式对话**
- 对话结束后，产出一份 `SKILL-draft.md`
- 用户拿到 `SKILL-draft.md` 后，再交给 `skill-creator` 去写真正的 SKILL.md、跑测试、迭代

**JZL-skill-grill 不做的事**（留给 skill-creator）：
- 写具体的 SKILL.md 指令
- 写 evals/evals.json
- 跑测试与基线
- 描述优化循环
- 打包成 .skill 文件

---

## 核心原则（大模型必须遵守）

1. **每轮 1 个焦点** — 不在同一轮混多个主题
2. **每轮内循环提问** — 模型逐个提问，用户逐个回答，直到本轮目标收敛（已确认信息足够明确）或本轮已询问 6 个问题，才进入下一轮
3. **已确认信息不丢失** — 跨轮累加，每轮开始时简短回显
4. **不替用户拍板** — 涉及选择时给推荐 + 理由，让用户决定
5. **不知道就说不知道** — 不编造技术细节，不确定的明确标注"待澄清"
6. **每轮结束生成独立 md 文档** — 每轮结束将该轮已确认信息 + 待澄清问题写入 `<当前工作目录>/SKILL-grill-round-<N>.md`
7. **6 轮全部完成后生成总稿** — 用户确认后，基于 6 份轮次文档合并生成 `SKILL-draft.md`

---

## 第 1 轮：破冰定位

**本轮目标：** 确认是不是要做 skill + 抓到最粗的轮廓

**开场白：**
> 好，咱们从最粗的轮廓开始。**你这个 skill 心里想干嘛？用一句大白话说就行，不用精确。** 顺便问一下，你最近是不是有一个**具体场景、一次具体对话、一段具体操作**，让你觉得"这事要是封装成 skill 就方便了"？

**必问问题（逐个提问，直到本轮结束条件满足）：**
1. "用一句大白话说，这个 skill 想干嘛？"
2. "你最近有个具体场景让你想做这个 skill 吗？能描述一下吗？"
3. "这个 skill 主要是**你自己用**，还是**团队 / 别人**用？"
4. "你对这个 skill 有没有已经写好的草稿、笔记、现成脚本？"

**本轮结束条件：** 意图描述清晰 + 适用人群已确认 + 是否有现成材料已确认（其中"意图描述"必须有具体的"做什么 + 给谁用 + 解决什么场景"三要素）

**产出文件：** `<当前工作目录>/SKILL-grill-round-1.md`，内容包含：本轮已确认信息 + 待澄清问题 + 一句话意图草稿

---

## 第 2 轮：触发场景

**本轮目标：** 把"什么时候该用这个 skill"想清楚

**开场白：**
> 好，截至现在我们记下了：[回显第 1 轮信息]。接下来聊聊**触发场景**——也就是用户在什么情况下会想起用你这个 skill。你估计用户**第一句话大概会怎么说**？能给我 1-2 个例子吗？最好口语化、带点个人风格。

**必问问题：**
1. "用户**第一句话**大概会怎么说？举 1-2 个例子（口语化）"
2. "有没有**特别像但其实不该触发**的场景？"（反向澄清，避免误触发）
3. "用户没提到 skill 名字时，凭哪些**关键词** Claude 应该意识到要用这个 skill？"

**本轮结束条件：** 触发关键词列表（3-5 个）+ 典型正向 prompt（2-3 个）+ 典型负向 prompt（1-2 个）+ 边界场景都已有答案

**产出文件：** `<当前工作目录>/SKILL-grill-round-2.md`

---

## 第 3 轮：输入输出契约

**本轮目标：** 把"喂什么进去、吐出什么来"想清楚

**开场白：**
> 好，触发场景记下了。接下来聊**输入输出**——用户**喂给**这个 skill 什么东西？skill 处理完**还给**用户什么？能给我一个**具体的样例**吗（可以脱敏）？

**必问问题：**
1. "用户**喂给**这个 skill 什么东西？（文件 / 文字 / URL / 代码 / 多选）"
2. "skill 处理完**还给**用户什么？（生成文件 / 文字 / 修改原文件 / 推送）"
3. "有没有**现成的样例输入**？能给我一个具体例子（可脱敏）？"
4. "**输出对格式有强要求**吗？（必须 JSON / Markdown / 特定 schema / 视觉上必须长什么样）"

**本轮结束条件：** 输入类型与例子 + 输出类型与例子 + 至少 1 个完整 I/O 对 + 至少 1 个边界输入都有答案

**产出文件：** `<当前工作目录>/SKILL-grill-round-3.md`

---

## 第 4 轮：工作流程设计

**本轮目标：** 把"skill 内部大致怎么干活"想清楚

**开场白：**
> 好，输入输出清楚了。接下来聊**工作流程**——凭你现在的想象，这个 skill 处理一件事**大概分几步**？你不用纠结细节，先粗分。

**必问问题：**
1. "这个 skill 处理一件事**大概分几步**？（粗分，3-7 步）"
2. "**哪一步是最有价值的、不可省的**？（核心价值主张）"
3. "**哪一步最容易出错 / 最需要人参与决策**？（human-in-the-loop 候选）"
4. "有没有**可参考的现有工作流**？（SOP / 公开方法论 / 其他工具的流程）"

**本轮结束条件：** 3-7 步工作流骨架 + 每步性质（确定性/判断性/HITL）+ 核心价值环节 + 高风险环节都已确认

**产出文件：** `<当前工作目录>/SKILL-grill-round-4.md`

---

## 第 5 轮：资源依赖与边界

**本轮目标：** 把"需要什么工具 / 哪些情况要处理"想清楚

**开场白：**
> 好，工作流清楚了。接下来聊**资源和边界**——这个 skill 要用**哪些工具**？有没有**必须捆绑的资产**（模板 / 提示词库 / 示例）？skill 处理**失败**的情况有哪些，各怎么办？

**必问问题：**
1. "skill 要用**哪些工具**？（文件读写 / bash / 网络 / 特定 CLI / MCP / 第三方 API）"
2. "有没有**必须捆绑的资产**？（模板 / 提示词库 / 示例文档）"
3. "skill 处理**失败的情况**有哪些？（格式错 / 网络断 / 用户撤回 / 中间结果不对）各怎么办？"
4. "**安全/合规边界**有没有？不能做什么？"

**本轮结束条件：** 必需/可选工具清单 + 捆绑资源清单 + 至少 2-3 种失败模式与对应处理 + 安全边界都已确认

**产出文件：** `<当前工作目录>/SKILL-grill-round-5.md`

---

## 第 6 轮：成功标准与测试

**本轮目标：** 把"怎么算 skill 做得好"想清楚

**开场白：**
> 好，资源和边界清楚了，这是**最后一轮**——聊**怎么算做得好**。什么样的输出你会觉得"这个 skill 帮大忙了"？反过来，什么样的输出会让你觉得"还是我自己来吧"？能不能想出 2-3 个**具体的测试场景**，就是用户真的会问的问题？

**必问问题：**
1. "什么样的输出你会觉得'这个 skill 帮大忙了'？（举一个最满意的假想输出例子）"
2. "什么样的输出会让你'还是我自己来吧'？（举一个失败的假想输出）"
3. "能不能想出 **2-3 个具体的测试场景**？（用户真的会问的问题，不是抽象的'测一下'）"
4. "对这些测试场景，**怎么算通过**？（客观可验证 / 需要人工判断）"

**本轮结束条件：** 典型"好"输出 + 典型"差"输出 + 2-3 个测试 prompt + 每个测试的通过标准都已确认

**产出文件：** `<当前工作目录>/SKILL-grill-round-6.md`

## 轮次文档格式模板

每轮结束写入的文档必须严格遵循以下格式：

```markdown
# Skill Grill — 第 <N> 轮: <轮次主题>

> 由 JZL-skill-grill 自动生成，记录第 N 轮对话的产出。
> 生成时间: <当前时间戳>

## 本轮已确认信息
<按本轮"必问问题"清单逐条列出已确认的回答，使用问答形式或要点形式>

## 本轮待澄清问题
- [ ] <问题 1>
- [ ] <问题 2>
> 这些问题未在本轮内收敛，会带到 SKILL-draft.md 第 7 节"遗留待澄清问题"。

## 一句话总结
<用一句话概括本轮的核心产出，作为回显和后续章节标题引用>
```

**注意：**
- 每轮文档**只记录本轮内容**，不重复历史信息
- "已确认信息"和"待澄清问题"是**两个独立板块**，不要混在一起
- "待澄清问题"是本轮循环提问中**始终未收敛**的项，而非"用户拒绝回答"的项

---

## 轮次收尾确认

每轮结束（已满足"本轮结束条件"）并写完 `SKILL-grill-round-<N>.md` 之后，**必须**使用 AskQuestion 工具询问用户：

**第 1-5 轮收尾：**
- 标题：Skill Grill 第 X 轮收尾
- 问题：第 X 轮已结束，文档已写入 SKILL-grill-round-X.md。是否进入第 X+1 轮？
- 选项：
  - "1. 把这一轮剩下的待解决问题答完"（触发循环澄清）
  - "2. 直接进入下一轮"（跳过本轮遗留问题）

**第 6 轮收尾：**
- 标题：Skill Grill 第 6 轮收尾
- 问题：6 轮对话已全部完成，文档已写入 SKILL-grill-round-6.md。是否开始合并生成 SKILL-draft.md？
- 选项：
  - "1. 生成 SKILL-draft.md"
  - "2. 解决 1-6 轮的遗留问题"

## 生成 SKILL-draft.md（定稿环节）

### 触发条件
- 第 6 轮已结束 + 用户明确选择"生成 SKILL-draft.md"

### 生成流程
1. **读取 6 份轮次文档**：依次读 `SKILL-grill-round-1.md` 到 `SKILL-grill-round-6.md`
2. **按章节映射合并**：每份轮次文档的"已确认信息"对应到 `SKILL-draft.md` 的对应章节
3. **汇总遗留问题**：从 6 份文档的"待澄清问题"汇总到 `SKILL-draft.md` 第 7 节
4. **写入总稿**：用 **Write 工具**生成 `<当前工作目录>/SKILL-draft.md`
5. **告知用户**：输出"总稿已生成到 `SKILL-draft.md`，可直接交给 skill-creator 消费"

### 轮次文档到总稿的章节映射

| 轮次文档 | 对应 SKILL-draft.md 章节 |
|---|---|
| `SKILL-grill-round-1.md` | 1. 元信息 |
| `SKILL-grill-round-2.md` | 2. 触发场景 |
| `SKILL-grill-round-3.md` | 3. 输入输出契约 |
| `SKILL-grill-round-4.md` | 4. 工作流骨架 |
| `SKILL-grill-round-5.md` | 5. 资源与依赖 |
| `SKILL-grill-round-6.md` | 6. 成功标准与测试 |
| 6 份文档的待澄清问题汇总 | 7. 遗留待澄清问题 |
| — | 8. 下一阶段建议（由模型自动生成） |
