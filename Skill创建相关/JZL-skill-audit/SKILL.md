# JZL-skill-audit

> Skill Inspector — 对任意 WorkBuddy Skill 进行静态审查或运行时审查，输出结构化报告并提供自愈建议。

**使用场景**：新 Skill 上线前自检 / Skill 实际运行后复盘 / Skill 修改后回归测试

---

## 快速开始

### 触发方式

```
/JZL-skill-audit <skill名称或路径> [static|runtime]
```

- **不带参数**：交互式引导（询问 skill 路径和审查类型）
- **带 skill 路径**：进入交互式确认，选择审查类型
- **带 `static`/`runtime` 关键字**：跳过选择，直接进入对应审查流程

### 示例

```
/JZL-skill-audit
/JZL-skill-audit lark-sheets
/JZL-skill-audit C:\Users\jzl\.claude\skills\lark-sheets static
/JZL-skill-audit my-awesome-skill runtime
```

## 核心概念

### 审查类型

| 类型 | 说明 | 审查范围 |
|------|------|----------|
| **静态审查** (`static`) | 不运行 Skill，基于文档扫描审查 | SKILL.md + scripts/ + references/ + assets/ |
| **运行时审查** (`runtime`) | 基于实际执行上下文审查 | 对话上下文 + 产出文件 + SKILL.md |

### 问题严重等级

| 等级 | 标识 | 定义 | 处理 |
|------|------|------|------|
| 🔴 致命 | `F` | 阻断使用、安全风险、合规违规 | **必须立即修复**后方可上线 |
| 🟡 警告 | `W` | 功能可用，但存在明显缺陷 | **建议优先修复**，下一迭代处理 |
| 🟢 建议 | `S` | 仅影响规范性、体验细节 | **按需修复**，可延后到后续版本 |

### 评分算法

```
维度得分 = max(0, 100 - 30×F - 10×W - 3×S)
加权总分 = Σ(维度得分 × 权重) / Σ权重
```

| 分数区间 | 评级 |
|----------|------|
| ≥ 85 | 优秀 |
| ≥ 70 | 良好 |
| ≥ 60 | 及格 |
| < 60 | 不合格 |

## 完整工作流

### Step 0：确认审查类型

```
用户触发 → 系统解析参数 → 若未指定类型则交互询问用户
```

询问话术：

> 请选择审查类型：
> 1. **静态审查** — 仅扫描 SKILL.md 及依赖文件，不运行
> 2. **运行时审查** — 基于对话上下文 + 产出文件审查
>
> 请回复 `1` 或 `2`（或直接说「静态」/「运行时」）

- 用户选择 `1` → 进入静态审查流程
- 用户选择 `2` → 进入运行时审查流程
- 用户未回复 → 等待确认

### Step 1：定位 Skill

读取目标 Skill 的 `SKILL.md`。如果用户提供的是名称而非路径，在以下位置搜索：

1. 当前工作目录（当前对话的根目录）
2. `~/.claude/skills/`
3. `~/.cursor/skills/`
4. `~/.cursor/skills-cursor/`

如果找到多个同名 Skill，列出供用户选择。

### Step 2：加载审查规则

按以下顺序加载配置（后面的覆盖前面的）：

1. 内置默认值（见 references/weights.yaml）
2. `JZL-skill-audit/references/weights.yaml`（如存在）

### Step 3：执行审查

#### 静态审查（14 个维度）

| # | 维度 | 权重 | 说明 |
|---|------|------|------|
| 1 | 元数据完整性 | 7.7 | YAML frontmatter 完整性、合法性 |
| 2 | 触发条件 | 7.7 | 触发逻辑明确性、无冲突 |
| 3 | 结构规范 | 6.1 | Markdown 层级、格式统一性 |
| 4 | 逻辑一致性 | 9.3 | 全文规则前后一致，无矛盾 |
| 5 | 内容完整性 | 7.7 | 无占位符、无关键流程缺失 |
| 6 | 工具引用正确性 | 9.3 | 工具名、参数、调用方式正确 |
| 7 | 路径有效性 | 7.7 | 所有文件路径引用真实存在 |
| 8 | 安全性 | 11.5 | 无安全风险、高危操作、隐私泄露 |
| 9 | 可读性 | 4.6 | 文本易于理解和维护 |
| 10 | 可重复性 | 7.7 | 任意 AI/人类可按文档复现 |
| 11 | 版本与变更管理 | 4.6 | 版本信息清晰，多人维护友好 |
| 12 | 输出规范约束 | 6.1 | 明确输出格式规范 |
| 13 | 权限与使用约束 | 6.1 | 声明适用范围和限制 |
| 14 | 注释与文档完备性 | 3.9 | 复杂逻辑有注释说明 |

详细规则见 `references/dimension-rules.md`。

#### 运行时审查（14 个维度）

| # | 维度 | 权重 | 说明 |
|---|------|------|------|
| 1 | 执行忠实度 | 9.9 | 实际执行路径忠实于文档 |
| 2 | 产出质量 | 8.7 | 产出文件符合预期 |
| 3 | 边界情况 | 8.0 | 非理想输入下的表现 |
| 4 | 错误恢复 | 8.0 | 错误后的降级和恢复 |
| 5 | 依赖声明 | 6.8 | 无未声明的隐式依赖 |
| 6 | 步骤冗余/遗漏 | 6.8 | 无多余步骤或缺失必要步骤 |
| 7 | 效率问题 | 5.4 | 执行效率合理 |
| 8 | 副作用 | 8.7 | 无预期外的状态变更 |
| 9 | 用户交互 | 6.8 | 与用户交互恰当 |
| 10 | 日志与可观测性 | 5.4 | 有足够日志用于问题排查 |
| 11 | 兼容性适配 | 4.1 | 不同运行环境表现一致 |
| 12 | 内容合规性 | 10.0 | 产出符合内容安全规范 |
| 13 | 分支逻辑有效性 | 8.0 | 所有分支逻辑可用 |
| 14 | 资源占用 | 3.4 | 资源消耗合理 |

详细规则见 `references/dimension-rules.md`。

### Step 4：生成报告

按照 `references/report-template.md` 渲染结构化报告。

**报告固定结构**（静态/运行时通用）：

```
# [Skill 名称] — [静态/运行时] 审查报告

## 一、基础信息
## 二、评分总览
## 三、问题清单（按：致命 → 警告 → 建议）
## 四、整体结论
## 五、附录：问题佐证
```

### Step 5：保存报告

1. **对话预览**：将报告渲染到当前对话
2. **MD 文件**：自动保存到被审 Skill 同级目录 `<skill>-audit-reports/`：
   - 文件名：`<YYYY-MM-DD>-<HHMMSS>-<static|runtime>-report.md`
   - 时间戳精确到秒，多次审查结果并存互不影响
3. **HTML 报告**：生成/更新 `audit-report.html`（见 `references/dimension-rules.md` HTML 规范）

## 自愈建议生成

每个问题的修复方案必须包含：

1. **位置**：`文件:行号` 或 `对话轮次`
2. **证据**：原始文本/日志片段
3. **修复方案**：具体、可操作的修改指令
4. **验证方法**：如何确认修复成功

修复方案模板：

```
**问题**：[问题描述]
**位置**：[文件:行号]
**修复方案**：
1. 在 [具体位置] 添加/修改/删除 [具体内容]
2. 建议的修改后代码/文本：
   ```
   [修改后的具体内容]
   ```
3. 验证方法：[如何确认修复成功]
```

## 异常处理

| 异常 | 处理方式 |
|------|----------|
| 用户未选择审查类型 | 等待用户确认；若持续不回复则终止 |
| Skill 目录不存在 | 提示用户确认名称；若确认不存在则终止 |
| SKILL.md 无法解析 | 报告 YAML 解析错误（致命），仍尝试审查正文 |
| 对话上下文为空（运行时） | 提示需要提供对话上下文，无法运行时审查 |
| 产出文件不存在（运行时） | 跳过产出质量维度，在报告中标注「未提供产出文件」 |

## 报告文件规范

### 报告保存路径

```
<被审Skill所在目录>/<skill-name>-audit-reports/
```

例如被审 Skill 为 `C:\Users\jzl\.claude\skills\lark-sheets\SKILL.md`，则报告保存在：

```
C:\Users\jzl\.claude\skills\lark-sheets\lark-sheets-audit-reports\
```

### HTML 报告规范

每次审查完成后，在 `<skill>-audit-reports/` 目录下生成/更新 `audit-report.html`。该文件为单文件全自包含（HTML + CSS + JS 内联，无需服务器即可直接打开）。

**核心功能**：

- 静态/运行时切换 Tab
- 历史报告列表（侧边栏，按时间倒序）
- 总览仪表盘（雷达图/柱状图、综合评级、问题计数）
- 问题详情（可展开，按严重等级分组）
- 趋势分析（如有 ≥ 2 条历史报告）

HTML 报告读取同目录下所有 `.md` 报告文件作为数据源。每次生成时扫描目录，重建索引数据。

详见 `references/dimension-rules.md` 的「HTML 可视化报告规范」章节。

## 评分参考

评分是参考而非裁决。最终是否上线、是否修复，由 Skill 维护者决定。

| 评级 | 上线建议 |
|------|----------|
| 优秀 (≥85) | ✅ 可上线 |
| 良好 (≥70) | ✅ 可上线，建议修复警告问题 |
| 及格 (≥60) | ⚠️ 有条件上线，需修复所有致命问题 |
| 不合格 (<60) | ❌ 不可上线，需重大修复 |
